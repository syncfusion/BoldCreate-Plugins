# Product lens

Use for a PRD such as `docs/product/prd.md`.

- **Users.** Each user group is named, with the job it needs done. No feature serves a user the document never names.
- **Problem.** The problem is stated before any solution, with evidence or a stated assumption behind it.
- **Features.** Every feature has a MoSCoW priority and traces to a user problem. Every Must traces to the MVP.
- **MVP scope.** The MVP is the smallest set that solves the main problem for one user group. Anything that can wait is marked Should or Could.
- **Success measures.** Each measure has a number, a time frame and a way to collect it.
- **Non-functional needs.** Performance, availability, security, privacy, accessibility and data retention are each stated or marked not applicable.
- **Out of scope.** Listed explicitly, and nothing in it appears elsewhere as a feature.
- **Consistency.** Terms match `GLOSSARY.md`; no two sections disagree on a number, a user or a priority.
- **Decisions.** Open questions are listed with an owner. Nothing is decided by vague wording such as "flexible", "intuitive" or "as needed".
